# Adaptive Michelangelo Finger

A robotic arm that reaches out to touch your fingertip — Michelangelo's
*Creation of Adam*, in hardware. Two stereo cameras locate a target in
3D space, and a 5-DOF arm points at it in real time, stopping just short
of contact.

This README covers the **hardware bring-up and software pipeline**:
system setup, servo control, camera calibration, kinematics, and the
tracking loop that ties them together, in the order they were actually
built. The mechanical design (3D-printed parts), the physical
construction process, and the hands-on camera positioning are
documented separately.

## Hardware

- Raspberry Pi 5 (`rpi502`), Ubuntu Server 26.04 LTS
- 2x Raspberry Pi Camera Module v3, mounted as a fixed stereo pair
- PCA9685 PWM controller driving 5 servos (I2C)
- A 5-DOF arm: base rotation (`base_joint`) → shoulder (`spin_joint`) →
  elbow (`basearm_joint`) → wrist (`midarm_joint`) → gripper
  (`gripper_joint`)

## How it works, end to end

1. Both cameras are calibrated as a stereo pair (intrinsics + the
   rotation/translation between them).
2. A one-time calibration locates the arm's own reference frame inside
   that stereo camera frame.
3. At runtime, a target (currently an ArUco marker, standing in for a
   fingertip) is detected in both camera images and triangulated into a
   3D point.
4. That point is converted into the arm's frame, then into joint angles
   via inverse kinematics.
5. The arm moves there, stopping a configurable distance short of the
   target so it never actually touches it.

## The build, in order

### 1. System and servo bring-up (`servo_calibration/`)

Ubuntu Server flashed, cameras and the PCA9685 wired over I2C. Each
servo's pulse-width-to-angle mapping is found once by hand
(`calibrate_servo.py`) and stored in `calibration_data/servos.json`.
`move_servo.py` then drives any calibrated servo to a given angle with a
speed-limited ramp (servos have no native speed control — commanding a
big jump directly would slam the arm at full servo speed). `arm_show.py`
chains poses into a demo choreography, and `go_home.py` returns the arm
to a known rest position.

### 2. Hardware failure: the Pi's I2C1 bus died

Mid-project, the Pi's hardware I2C1 bus (the header's dedicated
SDA/SCL pins) stopped responding — confirmed via kernel `"lost
arbitration"` errors, and reproduced identically across **three
different PCA9685 boards**, which ruled out a bad board and pointed at
the Pi's own I2C1 controller. The most likely cause: a brief
overvoltage during a "hot" rewiring session (the servo power rail is
5-6V; the Pi's GPIO pins are not 5V-tolerant). This kind of damage is
permanent — there's no repairable component at that level, just the
SoC itself.

The fix was a **software (bit-banged) I2C bus** on two different GPIO
pins (`dtoverlay=i2c-gpio` in `/boot/firmware/config.txt`, GPIO23/24
instead of the header's GPIO2/3), which has run reliably ever since.
The driver (`servo_calibration/pca9685_driver.py`) points at this bus by
default. Lesson learned: fully power everything down before touching
servo/PCA9685 wiring, and double-check 3.3V vs 5V pins before
reconnecting anything.

### 3. Stereo camera calibration (`camera_calibration/`)

`live_view.py` gives a live (MJPEG, since the Pi is headless) feed from
both cameras to position them by hand. Calibration uses a ChArUco
board (a checkerboard with embedded ArUco tags — detectable even
partially out of frame, unlike a plain checkerboard) generated by
`generate_targets.py`. One real-world snag: the printed board measured
25.6mm per square instead of the intended 25.0mm — the print pipeline
had silently rescaled it by ~2.4% (the PDF itself was verified correct).
Rather than reprinting, the *measured* size was used everywhere
downstream, which is standard practice and cost nothing in accuracy.

`capture_stereo_images.py` captures board images from both cameras with
live detection feedback, and `calibrate_stereo.py` computes each
camera's intrinsics and the rigid transform between them
(`cv2.calibrateCamera` + `cv2.stereoCalibrate`). Result: **~0.2px RMS
reprojection error per camera, ~0.4px for the stereo pair** — well
into "very good" territory for a hobby rig.

### 4. Locating the arm in camera space (`camera_calibration/calibrate_camera_to_arm.py`)

The stereo pair gives 3D points in *camera* space; the arm needs them in
*its own* frame. A full hand-eye calibration (move the arm through known
poses, observe a marker on it) was skipped, since it needs forward
kinematics — which didn't exist yet at this point in the build. Instead:
two ArUco tags taped flat on the ground next to the (non-flat, often
arm-occluded) base, with their positions measured by hand and their
*orientation* (the floor's normal) read directly from their own
triangulated corners. Two known positions plus a detected normal fully
constrain the transform — no iterative fitting needed. Result: **1.8%
distance error, 3.2° agreement** between the two tags' independently
measured normals — both within the tolerance expected from a
ruler-and-tape-measure calibration.

### 5. Kinematics (`kinematics/`)

The three parallel-axis joints (shoulder/elbow/wrist) reduce the whole
arm to a textbook planar-arm-plus-base-rotation problem. Forward
kinematics is a closed-form projection; inverse kinematics uses the law
of cosines. The arm has one more joint than a 3D position needs, so
reaching a given point is never unique (same redundancy as a human
elbow) — two solvers handle that:
- `inverse_kinematics_search` tries wrist angles until it finds one that
  keeps every joint within its calibrated limits (a real case surfaced
  during testing: the naive fixed-wrist solution demanded a 114° elbow
  bend — beyond the servo's ±90° range — for a target that turned out to
  be perfectly reachable at 29°/88°/45° once the wrist was allowed to
  bend too).
- `inverse_kinematics_pointing` additionally keeps the last arm segment
  literally pointed at the target (not just its tip landing nearby) —
  closed-form, since the segment's fixed length pins the geometry
  completely once you know how far short of the target it should stop.

Both were validated with thousands of randomized forward→inverse→forward
round trips: sub-micron position error, and sub-0.001° angular
alignment error for the pointing solver.

### 6. The tracking loop (`tracking/follow_target.py`)

Everything above, glued together: detect the target tag in both
cameras → triangulate → convert to the arm's frame → back off by a
safety standoff → solve inverse kinematics → drive the arm there,
continuously. A live annotated preview and optional video recording are
included. The arm's own fingertip position is trusted from the
kinematics alone (open-loop) rather than visually verified with a
second marker — accurate enough in practice that this was a deliberate
choice, not a shortcut waiting to be fixed.

## Repository layout

| Directory | What's in it |
|---|---|
| `servo_calibration/` | Servo calibration, angle-based control, demo choreography, home position |
| `camera_calibration/` | Stereo camera calibration, camera-to-arm frame calibration, target generation |
| `kinematics/` | Forward/inverse kinematics, pure geometry, no hardware dependency |
| `tracking/` | The live visual tracking loop |
| `calibration_data/` | Generated calibration results (not versioned — device-specific) |

Each directory has its own README with full usage details.

## Running it, in order

```bash
# 1. Calibrate each servo (once per servo)
python3 -m servo_calibration.calibrate_servo --channel 0 --name base_joint
# ... repeat for channels 1-4

# 2. Position and calibrate the stereo cameras
python3 -m camera_calibration.live_view
python3 -m camera_calibration.generate_targets   # print the ChArUco board + tags
python3 -m camera_calibration.capture_stereo_images
python3 -m camera_calibration.calibrate_stereo

# 3. Locate the arm in camera space (two ArUco tags on the floor)
python3 -m camera_calibration.calibrate_camera_to_arm \
    --marker1-id 2 --marker1-x-mm <measured> --marker1-y-mm <measured> \
    --marker2-id 3 --marker2-x-mm <measured> --marker2-y-mm <measured>

# 4. Point at a tracked ArUco tag
python3 -m tracking.follow_target --point-gripper
```

## Results achieved

- Stereo calibration: ~0.2px RMS reprojection error per camera, ~0.4px
  for the stereo pair.
- Triangulation accuracy, checked against a known 25.6mm spacing across
  318 real measurements: -0.03mm mean error, 0.13mm standard deviation.
- Camera-to-arm frame: 1.8% distance error, 3.2° normal agreement
  between two independent measurements.
- Kinematics: sub-micron forward/inverse round-trip error; sub-0.001°
  pointing accuracy.
- A working closed-loop demo: the arm visually tracks a moving target
  and points its gripper at it in real time, stopping short of contact.

## Known limitations

- The arm's own tip position is never visually verified — only computed
  from calibration + commanded angles. Accurate enough in testing that a
  planned second-marker verification step was deliberately not pursued.
- The target must currently be an ArUco tag, not a bare hand — a
  deliberate simplification to validate the geometric pipeline against a
  reliable detector before tackling fingertip detection.
